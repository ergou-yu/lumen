# Lumen · Lumi 私人 AI 代理

> 莫奈印象派界面，零 npm 依赖，可自托管的个人代理。当前版本：1.6.1。

Lumi 能研究资料、管理目标和记忆、生成文件，并在你授权后调用应用或使用隔离桌面。新版将普通任务放到服务桥执行：关闭网页后，任务仍继续；回来可检查成果、补充指令和审批。

**它尚未完整复刻 Meta Muse 或 ChatGPT Dots。** 本版补齐持续任务、计划、共享状态等核心机制，原生客户端、完整云端电脑服务、实时语音通话、完整插件生态及 Muse 的安全基础设施仍有差距。逐项依据、改动前后状态和未验收项目见 [功能核查报告](docs/parity-audit-2026-10-02.md)。

## 开始使用

```bash
git clone https://github.com/ergou-yu/lumen.git
cd lumen
node server.js
```

需要 Node ≥18。默认打开 `http://127.0.0.1:8787`；`PORT=9000` 可换端口，`LUMEN_NO_OPEN=1` 禁止自动开浏览器。

1. 在设置 → 模型接入，配置自己的模型、端点和 Key。
2. 在 **活动 → 启用当前模型**，明确将配置交给服务桥后台执行。配置保存在私有文件，接口不回传密钥。
3. 从聊天或活动页委托工作。服务桥保持运行即可关掉网页；回到活动页检查成果。
4. 需要应用操作时先配置连接器；真实 GUI 和隔离代码执行还需要 Docker Desktop。

没有模型时保留明确标注的演示模式。直接打开 `index.html` 可体验静态界面；持续任务和受保护接口应从服务桥网址访问。

## 持续工作能力

| 能力 | 实际实现 |
|---|---|
| 后台任务 | JSON 检查点落盘，最多同时执行 2 项，关页继续，读取任务重启后恢复 |
| 工作中调整 | 独立暂停/继续/停止/补充指令；新指令使尚未执行的旧模型计划作废 |
| 独立子任务 | 最多 3 项，父任务等待汇总；停止父任务不误停子任务，无嵌套 |
| 计划与跟进 | 一次性/间隔/每天/工作日，时区、截止时间、编辑/暂停/删除、任务 sleep/wake |
| 有意义的通知 | 活动页、Webhook、原私聊渠道回传；观察来源不变时抑制重复完成通知 |
| 共享状态 | 同一服务桥共享活动、目标、记忆、建议和计划；旧聊天与浏览器设置仍各自保存 |
| 个性化建议 | 按已知目标和偏好研究并保存建议，点击委托才执行；原 15 张示例卡保留 |
| 共享记忆 | 手动迁移旧条目，查看/修改/遗忘/导出；可选 Hindsight 召回和沉淀 |
| 服务端审批 | 外部写入保存固定动作、收件人和内容，批准一次；失效审批拒绝，回执不确定不重发 |
| 模型 | 后台支持 Anthropic、OpenAI 兼容、Gemini，含图像观察；兼容端点须支持对应接口 |
| 代码执行 | 需批准的 Node/Python Docker 临时容器：禁网、普通用户、15 秒、256MB/1CPU |
| 生图 | 支持 Images API 的后台端点可生成真实 PNG；模型可配置，调用前批准。程序画作仍属演示艺术 |
| 语音 | 浏览器识别与朗读的连续轮次，可同时打字，结束语音不停止任务；并非 Realtime 通话 |
| 外观 | 原莫奈头像保留；活动页新增名字、形状、颜色、眼睛、眼镜、配饰预览 |

每个任务最多 64 个模型步骤，每轮最多 16 步。模型规划并不保证成功，活动页保留实际错误和工具回执。外部写入执行中，停止不能撤销已经产生的后果。

## 页面

聊天、动态、灵感、目标、文件、记忆、计算机、技能，以及新增的 **活动**。活动页是服务端持续数据的入口；原目标/记忆页主要管理浏览器本地条目，迁移后可在活动页跨设备管理。

“灵感”的个性化建议与后台共用目标、记忆。通用动态简报保留；没有默认监听全部账号的行为。计划中的只读研究可保存建议与研究笔记，不允许发送、写产物、控制电脑或执行代码。

## 电脑和文件

轻量 LumenBox 提供真实搜索、网页正文阅读、链接访问和 `vm-home/` 工作区，不运行网页 JS。LumenBox Desktop 使用本机非特权 Docker 容器中的 Chromium、Xvfb、VNC/noVNC，可查看 Live 画面、接管并归还控制权。模型桌面操作串行，接管状态由服务器执行，已在途动作无法倒退。

后台聊天会等待桌面任务的真实结果，失败和需要本人操作不会显示完成。发送「继续」或在计算机页点「继续原任务」，会先重新观察并核实已有操作，再接续原任务。旧版把提交误记为完成的记录会自动纠正，原任务、证据和审计记录保留。

模型菜单提供 `glm-5.3-flash` 图片模型。使用 GLM-5.3 聊天时，桌面规划自动使用同一连接的 GLM-5.3-Flash 读取截图；当前端点需要支持该模型。GLM-5.3 本身只接受文字，不会假装读到截图。已发现的桌面优先用 HTTP 健康检查，状态轮询合并并缓存，避免 Docker CLI 较慢时并发堆积；连接失败会显示实际错误。

桌面镜像基于 **Debian 13**，底部 Dock 可打开 Chromium、LXTerminal、PCManFM、GIMP、Inkscape、Blender、Kdenlive 和外观面板。包含 Node、Python、pip/venv、FFmpeg、Pillow、ReportLab 与 PDF 工具。终端默认进入 `~/Downloads`，与计算机页的 `vm-home/` 工作区共享文件。3D 和视频在容器里使用 CPU/软件渲染，实际速度受分配的资源限制。

默认外观是 **Lumi · 燕麦黄与雾粉**：Lumi 插画、小花与星星壁纸，雾粉强调色 `#d5a4b2`，奶油色圆角 Dock。在「计算机 → 桌面外观」或 Dock 的 Lumi 头像中，还可选择 60 套内置壁纸组合，上传 PNG/JPEG/静态 SVG（最大 6 MB）、修改窗口标题栏与 Dock 强调色、恢复默认。外观与浏览器数据保存在 `lumen-box-home` 私有卷中，重建容器后仍保留；应用内部配色由各应用管理。

Lumi 的燕麦黄与雾粉专属壁纸保存在 `vm-box/assets/lumi-oat-rose-wallpaper.png`，配套强调色是 `#d5a4b2`。壁纸由内置 imagegen 根据 Lumi 头像生成，完整提示词保存在同目录的 `lumi-oat-rose.prompt.txt`。Dock 使用奶油色圆角托盘，点击 Lumi 头像可打开桌面外观面板。

工作区支持上传、阅读、编辑、下载。新后台文本文件操作拒绝路径穿越和符号链接逃逸。HTML/JS 可作为产物文件生成，但尚无在线托管、分享或受控交互预览；完整 PDF、Office 与视频产物管线未实现。

Docker 镜像首次使用可在计算机页构建，或：

```bash
docker build -t lumen-box vm-box/
```

更新应用后，结束桌面任务并重启服务桥、刷新网页。服务桥会根据镜像内容版本自动升级本工作区已运行的旧桌面；已停止的桌面会在下次启动时升级。先构建镜像再替换容器，旧容器保留为 `lumen-box-previous-*` 备份，启动失败时恢复旧桌面。下载工作区与 `lumen-box-home` 卷会继续复用；原出厂壁纸升级到 Lumi 主题，用户自己选择的配色和上传图片会保留。构建失败时可在计算机页点击「更新 Linux 桌面」重试。首次安装创作工具会下载较多软件包。这仍是独立 Linux 容器，运行位置取决于服务桥所在主机；不会自动变成远程云主机。

明确“用我的电脑”才走 QCU 本机操作桥，需要安装 qcu CLI 并允许对应系统权限。旧的可选软沙箱终端运行在宿主，工作目录限制不能替代系统隔离；`LUMEN_VM_SHELL=0` 可关闭它。新后台代码工具使用禁网容器。

## 应用与消息入口

连接器可配置 IMAP/SMTP、Google、Microsoft Graph、飞书及已有应用路径。在活动 → 应用权限明确启用、授予读取或写入，默认禁用，服务端检查实际调用；邮件统一入口使用 Google/微软时还检查实际账号的权限。邮件、日历、文档动作取决于实际账号、OAuth scopes 与应用授权；不能把一个开关视为已连接。

设置 → 应用连接中，使用者点击“连接飞书账户 / Google / Microsoft”进入官方登录、授权，返回后自动显示账户。App ID / Client ID 配置收进默认折叠的“高级设置”，由应用维护者完成一次；可从环境变量提供应用凭据，无需每个使用者填应用 ID。尚未配置应用时明确显示“应用待配置”。飞书支持 OAuth v3 + PKCE、令牌续期、断开连接，用户授权后的消息、文档及日历动作使用用户身份；原有应用机器人与群 Webhook 保留。

维护者配置方法见 [OAuth 应用配置](docs/deployment.md#oauth-应用配置一次)。飞书账户授权目前支持国内版，自建应用限本企业，跨企业需商店应用；开放平台注册的应用需要服务端 Secret，不能分发到公开客户端。Google 使用 Web 应用；Microsoft 本机可用公共客户端 + PKCE，云端使用 Web 应用与服务端 Secret。设备码保留为微软的高级备用入口。仓库不包含任何已注册的公共 OAuth 应用，也不复用其他产品的 Client ID。

收件箱新增完整 IMAP/Gmail/Graph 入口，支持未读筛选、中文 MIME 和 IMAP literal 分包。后台读取过滤明显验证码/重置密码邮件主题；这不是完整正文敏感信息分类。

活动页可配置 **Slack / Teams / WhatsApp** 的本人文本私聊入口。需要自己的平台应用、凭证、本人 ID 和公开 HTTPS webhook：

| 平台 | 回调 | 防护 |
|---|---|---|
| Slack | `/channels/slack/events` | 原始字节 HMAC、时间窗口、事件去重、绑定本人 DM |
| Teams | `/channels/teams/events` | Bot Framework JWT/JWKS、issuer/audience/服务 URL/渠道背书、本人租户与 DM |
| WhatsApp | `/channels/whatsapp/events` | challenge、HMAC、消息时效与去重、绑定本人号码 |

任务完成或等待审批时回传原私聊。当前未使用真实平台账号进行端到端验收；不支持群聊、附件或原厂渠道全部功能。审批在受保护活动页完成。Instagram 开关属于浏览器操作倾向，没有原生 Instagram API。

## 模型配置与数据

页面执行模型仍可浏览器直连，Key 在该浏览器 localStorage。后台启用时另存 `lumen-agent-model.json`（0600）。也可仅用环境变量：

```bash
LUMEN_MODEL_TYPE=openai \
LUMEN_MODEL_BASE=https://api.openai.com/v1 \
LUMEN_MODEL_NAME=你的文本模型名 \
LUMEN_MODEL_API_KEY=你的Key \
node server.js
```

`LUMEN_MODEL_TYPE` 支持 `openai` / `anthropic` / `gemini`，默认 `anthropic`。OpenAI base 通常包含 `/v1`；Anthropic base 可带或不带 `/v1`；Gemini base 应包含版本路径，如 `/v1beta`。生图可用 `LUMEN_IMAGE_MODEL` 或活动页填写兼容端点支持的图像模型。图片能力取决于端点，文本模型的 Key 不自动意味着可以生图。

旧 `/v1` 本地转译网关仍针对 Anthropic 上游，别把 OpenAI 上游当作该转译网关。新后台直接支持三种协议。

默认数据位于仓库本机目录，均已加入 `.gitignore`；`LUMEN_DATA_DIR=/你的私有目录` 可集中保存后台状态、连接器配置与工作区。服务不读取第三方工具的模型配置。数据提供给你配置的模型、应用或 Hindsight 时，会按所选端点离开本机；“自托管”不意味着模型调用永不出网。

可选 Hindsight 的启用、检索、反思与遗忘仍在原记忆设置中。它需要自己的模型与部署，不属于零依赖核心；本轮没有验收真实 Hindsight 服务。删除浏览器数据不会同时删除服务端状态、Hindsight 或平台聊天历史。

## 安全边界和部署

默认仅监听回环地址。局域网访问或长期部署请设置访问口令，公网还需 HTTPS 与常在线主机：

```bash
LUMEN_HOST=0.0.0.0 LUMEN_ACCESS_TOKEN=你生成的高强度口令 node server.js
```

口令通过登录页换取 HttpOnly、SameSite=Strict 会话；API 支持 Bearer。数据变更检查同源，消息平台回调通过各自签名校验。容器部署说明见 [deployment.md](docs/deployment.md)。未替你购买或部署云主机，本机休眠/关机时本地代理无法继续。

当前 Sentinel 是动作审批层，文本抓取具备 DNS/IP 固定与重定向复查。它没有拦截 Chromium 全部网络出口，也没有独立安全模型、内核污点传播、Meta authd 或硬件保密体系。凭证文件 0600 是本机文件权限，并不是加密保险库。个人服务桥没有多租户隔离。

规则有允许、明确提到动作、先问、转交本人四档；明确要求采用可信用户指令关键词匹配。安全硬限制、敏感桌面动作及后台对外写入仍不能由“全自动”绕过。旧页面执行引擎的对外应用写入已被服务端拒绝，需切换后台任务；浏览器里的旧倾向开关不授予后台应用权限。

## 验证与更新

```bash
npm test
```

自动检查覆盖后台持久化、未知外部结果不重发、权限、计划/时区/DST、子任务、模型格式、渠道签名、IMAP 分包、OAuth 跳转与 PKCE、单次回调、断开连接期间的在途授权、服务端凭据隔离、Microsoft 设备码请求和版本更新。平台与模型测试使用本地模拟，不代表真实账号端到端成功。附带 Node 18/22 的 [Actions 工作流示例](docs/ci-test-workflow.yml)。当前 GitHub 登录未授予 workflow 权限，示例尚未安装到 Actions，远端 CI 未运行。

设置 → 更新分别显示本地代码版本与当前服务版本。拉取代码不会替换正在运行的 Node 进程；显示“待重启”时，请在原终端停止服务并用原启动命令重新启动，再刷新网页。应用内更新使用 `git pull --ff-only`，本地未提交修改会拒绝覆盖。离线或远端检查失败时显示无法确认，不报告“已是最新”。

主要结构：`lib/` 为后台运行器/模型/渠道/网络/IMAP，`js/continuity.js` 为持续工作界面，`server.js` 为服务桥，`vm-box/` 为桌面镜像，`skills/` 为内置技能，`tests/` 为自动验证，`docs/` 为调查与部署说明。

Lumen 是独立开源项目，与 Meta 或 OpenAI 产品没有关联。采用 [MIT](LICENSE)。
