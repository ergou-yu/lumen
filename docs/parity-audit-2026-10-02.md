# Lumi 与 Meta Muse、ChatGPT Dots 的功能核查

核查日期：2026-10-02。目标版本：Lumen 1.5.0。结论：**改动前没有完整复刻；本版补齐了核心持续代理机制，但仍不是两款产品所有功能的完整等价实现。**

这里的“所有”按两款产品公开资料中可以确认的功能逐项核查，不按首页按钮数量或营销名称打分。未进入受邀账号逐项实测，也无法验证未公开功能。下面将代码已经具备、仅有接口、需要外部部署，以及仍缺少的能力分别标出。没有把未来计划算作已发布功能，也没有编造一个“复刻完成百分比”。

## 两款产品究竟提供什么

Muse 的公开设计强调：把目标转成计划，持续处理多项工作，拥有独立电脑，跨对话记忆，主动提出 Ideas，并让用户查看活动和权限。文档、网页及交互工具是工作成果的一部分；浏览过程可以接管。它不仅是聊天界面。[Meta 发布介绍](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)、[Muse 产品设计](https://introducing.muse.ai/)

Dots 的入口是一个可定制的代理。它可以承担长期责任，使用云端电脑，启动独立任务，安排跟进，并通过不同入口保持同一身份。关闭本人的设备后，云端工作仍可继续。[Dots 总览](https://learn.chatgpt.com/docs/dots)

Dots 的任务、责任、计划和记忆有各自的生命周期；主对话暂停并不等于停止每个独立任务。跨入口记忆也不等于无条件把私人对话透露给群聊。[任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory)、[控制与审批](https://learn.chatgpt.com/docs/dots/controls)

Muse 的安全设计另有独立的基础设施：隔离运行环境、凭证代理、独立审批层，以及覆盖网络出口的 Sentinel。官方还公开了内核污点传播和安全分类机制。Docker 容器加若干按钮关键词检查，不能称为完整复刻这一安全体系。[Meta 安全架构](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)

## 判定方法

“具备”表示已有实现及对应验证，限于注明的前提；“部分”表示核心路径可用，但范围、体验或基础设施不同；“待接入”表示接口存在，未使用真实平台账号验收；“缺少”表示当前没有相应实现。

证据主要来自 `server.js`、`js/agent.js`、`js/ui.js`、`js/store.js`、`vm-box/`，以及本版新增的 `lib/`、`js/continuity.js` 和 `tests/`。API、模型与账号接通不等于任务必然成功；网络、模型工具规划和权限都影响结果。

本组的公开依据为 [Muse 产品设计](https://introducing.muse.ai/) 和 [Dots 总览](https://learn.chatgpt.com/docs/dots)。具体记忆范围参考 [Dots 任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory)。

| 功能 | 改动前 | 1.5.0 与实际边界 |
|---|---|---|
| 主对话 | 具备 | 保留聊天及模型接入；后台任务完成后写回原会话 |
| 多个独立对话 | 具备 | 浏览器保存历史，后台按会话选择最近成果；全量聊天仍不跨设备同步 |
| 不等上一项完成就委托新工作 | 部分 | 后台队列最多同时执行 2 项；桌面操作串行防止互相抢电脑 |
| 工作中补充指令 | 部分 | 活动页支持补充；模型调用期间到达的新指令使旧计划作废 |
| 自定义名字和语气 | 具备 | 原设置保留；后台共享名字，后台尚未同步全部语气设置 |
| 形状、颜色、眼睛、眼镜、配饰 | 缺少 | 新增圆点/叶子/星光和外观预览；不是原厂动画渲染器，聊天仍用原有莫奈头像 |
| 唯一代理 handle、账号身份 | 缺少 | 没有全球用户名系统 |
| 从目标和偏好生成建议 | 静态 15 张示例卡 | 新增模型生成建议，保存依据与委托文本；点击委托后才执行 |
| 无需逐次发问的主动发现 | 部分 | 可授权只读计划研究；没有默认擅自监听整个账号的系统 |
| 长期目标、步骤与完成进度 | 浏览器本地 | 新增服务端共享目标、手动建立与勾选，模型也可拆步骤 |
| 可查看、修改、遗忘记忆 | 本地条目，另有可选 Hindsight | 新增后台共享条目；支持手动迁移、修改、遗忘、导出 |
| 用户事实与代理研究笔记 | 没有明确后台区分 | 支持记忆 kind；研究笔记独立标签，模型提示禁止把推测当用户事实；无强制事实验证器 |
| 跨设备状态 | 部分桌面任务 | 同一服务桥共享活动、计划、目标、记忆和建议；旧聊天、设置、文件页索引仍在各浏览器 |
| 多入口共同记忆 | 缺少 | 已实现本人私聊通道使用同一后台记忆；未验收平台端到端 |
| 原生 Mac、iOS、Android 客户端 | 缺少 | 响应式网页和主屏幕快捷方式；没有原生客户端 |

公开依据为 [Dots 任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory) 及 [Dots 控制](https://learn.chatgpt.com/docs/dots/controls)。

| 独立子任务及汇总 | 缺少真正服务端子任务 | 最多 3 个子任务、禁止嵌套；父任务等子任务终结后再汇总 |

| 子任务之间任意协调、独立模型/环境 | 缺少 | 可查活动结果；没有原厂跨环境任务体系或任意嵌套 |

| 夏令时与错过运行 | 没有完整规则 | 按目标时区排程；错过多轮合并一项，同计划不重叠 |
| 修改、暂停、删除计划 | 部分 | 支持；取消计划不撤销已经开始的执行 |
| 自行 sleep/wake | 缺少 | 已委托任务可安排 1 分钟至 30 天内跟进；用户可调整/停止 |
| 指定来源的事件触发 | 部分轮询 | 私聊 webhook 入站可触发；没有邮件/日历等各类变化订阅总线 |
| 通知有意义的变化 | 部分 | 活动通知、Webhook、原渠道回传；有来源观察时按来源哈希去重，不按随机措辞制造变化 |
| 各渠道/各任务通知目的地与偏好 | 部分 | 私聊原渠道回传、计划“变化/每次”；没有任意目的地路由与完整通知矩阵 |
| 活动记录、成果、审批和错误 | 散在聊天、桌面与设置 | 新增统一后台活动页，保留执行记录、成果下载与真实错误 |
| 暂停、继续、停止、删除 | 部分 | 后台单任务控制；外部动作执行中不能以停止假装撤销 |
| 原厂 Work/Codex 任务创建和继续 | 缺少 | 自建任务系统；没有连接 OpenAI 内部任务基础设施 |

## 对照五：权限、隐私和安全

依据：[Dots 控制](https://learn.chatgpt.com/docs/dots/controls)、[Dots 电脑与应用](https://learn.chatgpt.com/docs/dots/computers-and-apps)、[Muse 安全架构](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)。

| 功能 | 改动前 | 1.5.0 与实际边界 |
|---|---|---|
| 应用读/写独立权限和断开 | 部分开关仅影响浏览器提示词 | 新增服务端启用/读取/写入权限，默认禁用；按每次调用检查，邮件别名还检查实际账号，写入必须批准具体内容 |
| 允许/明确要求/先问/转交本人四档 | 三档 | 新增“明确提到动作”；采用可信用户指令的关键词匹配，非原厂语义审批模型 |
| 审批固定动作、目标与内容 | 前端审批为主 | 后台审批由服务器保存不可变副本，UUID 失效校验；旧页面执行引擎不能直接完成对外应用写入，必须切换后台 |
| 超时/重启不重复发送 | 缺少统一保护 | 外部写入失去回执时标为不确定，禁止自动重试 |
| 私密登录、凭证不入模型 | 已有本地安全区 | 保留独立凭证文件；secret 引用必须审批。页面内容/截图仍可能暴露登录后的数据；没有自动脱敏体系 |
| 敏感点击/键盘提交检查 | 有关键词检查但有绕过路径 | 增加 Enter/Return/space 等审批，绑定页面/元素/内容；关键词无法证明识别所有敏感行为 |
| SSRF 与 DNS 重绑定 | 主机字符串检查 | 文本抓取固定已验证公共 IP，每次重定向复查；GUI 导航只预检，不能覆盖浏览器所有子资源/脚本/重定向出口 |
| 访问鉴权 | 默认无认证回环服务 | 新增可选访问口令、HttpOnly 会话与同源变更守卫；容器部署要求口令 |
| 独立安全模型/提示注入分类器 | 缺少 | 仍缺少；系统提示和关键词不能替代独立安全分类器 |
| 全出口网络代理、细粒度授权、内核污点传播 | 缺少 | 仍缺少；当前 Sentinel 是动作检查，不是 Meta 的 L4/L7 出口和 LSM/eBPF 系统 |
| 凭证代理进程、内核认证 IPC、安全信封 | 缺少 | 仍缺少；本地 0600 文件不是 authd 或硬件保密环境 |
| 企业权限、多用户租户隔离 | 缺少 | 仍是个人服务桥；一个口令不能构成多租户系统 |
| 删除所有数据及云端记忆治理 | 浏览器清空与 Hindsight 入口 | 新增后台单条删除/导出；旧清空按钮不等于清空服务器、Hindsight 和平台历史 |

## 使用新版

运行 `node server.js`，从该服务桥网址进入。设置里接入模型后，在“活动”点“启用当前模型”，明确将模型配置保存到服务桥私有文件；新聊天随后可由后台执行。“灵感”生成的个性化建议只保存建议；选择“交给 Lumi”才委托工作。

在其他设备访问同一服务桥，“活动”显示同一份后台数据。关闭网页不停止服务；本机休眠/关机仍会让本地服务中断。常在线部署说明见 [部署文档](deployment.md)。要获得原产品的全部能力，还需要实现表中明确缺少的基础设施、产物管线、客户端与平台接入，不能用更名或按钮补齐来代替。
